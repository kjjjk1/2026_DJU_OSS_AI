# DataClinic 최종 결과보고서

**2026 DJU OSS·AI 해커톤 | AI 기반 데이터 정제 의사결정 지원 서비스**

## 1. 프로젝트 개요

데이터 분석 경험이 적은 사용자는 CSV에서 결측값이나 이상 후보를 발견해도 어떤 처리 방법이 적절한지 판단하기 어렵다. 행 삭제나 값 대체는 표본 구성과 통계를 바꾸므로, 같은 데이터라도 정제 방식에 따라 분석 결과가 달라질 수 있다.

DataClinic은 데이터 품질 문제를 찾고, 처리 방법을 적용하기 전에 그 영향을 비교할 수 있도록 만든 웹 프로토타입이다. AI는 진단과 비교 결과를 바탕으로 추천 근거와 주의사항을 설명한다. 사용자는 원자료와 비교 결과를 확인하고 적용할 방법을 승인한다.

## 2. 요구사항 및 달성 현황

| 요구사항 | 구현 결과 |
| --- | --- |
| 데이터 품질 진단 | CSV의 결측값, 중복·충돌 행, 수치형 이상 후보를 표시한다. 내장 예시로도 시작할 수 있다. |
| 분석 목적에 따른 AI 정제 안내 | 진단 요약, 문제를 확인할 순서, 처리 방법의 근거와 주의사항을 안내하는 API 연동 코드를 구현했다. |
| 처리 전 주의사항 제시 | 라벨·식별자의 결측이나 집계값 변경처럼 원자료 확인이 필요한 경우를 설명한다. |
| 정제 결과 시뮬레이션 | 처리 전후 행 수, 결측값 수, 평균·중앙값 등 관련 지표를 비교한다. |
| 사용자 승인과 결과 내보내기 | 사용자 승인으로 새 버전을 만들고, 승인 이력 조회, 취소, 이전 버전 복원, 결과 CSV 내보내기를 지원한다. |

## 3. 시스템 구성 및 데이터 흐름

| 구성 요소 | 역할 |
| --- | --- |
| 브라우저 | HTML·CSS·JavaScript로 화면을 제공하고 CSV 읽기, 품질 진단, 처리 결과 비교, 버전 관리와 내보내기를 수행한다. |
| Node.js 서버 | 앱 화면을 제공하고, `POST /api/ai` 요청을 외부 AI API에 중계한다. `GET /healthz`는 서버 응답 상태를 확인하는 데 사용한다. |
| OpenAI 호환 API | Chat Completions 형식으로 설명을 생성한다. 서버의 기본 모델은 `gpt-4o-mini`다. |
| Render Web Service | 화면과 API 중계 서버를 같은 주소에서 제공하도록 구성한 배포 대상이다. |

사용 흐름은 **CSV 또는 예시 선택 → 분석 목적 설정 → 품질 진단 → 처리 방법 비교 및 AI 안내 확인 → 사용자 승인 → 이력 확인 및 결과 내보내기**다.

CSV 파일 읽기와 정제는 브라우저에서 수행한다. AI 안내를 선택하면 컬럼명, 문제 설명과 근거 문구, 진단 결과, 집계 통계 등의 요약 정보가 서버를 거쳐 API 제공자에 전달된다. API 키는 서버 환경 변수에 보관한다.

## 4. 핵심 구현 방식

- **품질 진단** · 결측값과 중복·충돌 행을 찾아 검토 항목으로 제시한다. 수치형 열에서는 1사분위수와 3사분위수 사이의 범위(IQR)를 바탕으로 수치형 이상 후보를 찾는다. 후보 상세 화면에 Q1, Q3, IQR, 계산 구간과 후보 수를 표시한다. 결측값과 형식·범위 위반은 계산에서 제외한다. 유효 수치가 4개 미만이거나 IQR이 0인 열은 미평가 사유를 보여준다. 열별 계산 근거는 결과 JSON에도 포함된다.
- **처리 방법 비교** · 문제 유형과 선택한 처리 방법에 따라 임시 결과를 계산하고, 현재 버전과 비교한다. 사용자는 행 삭제나 값 대체가 분석에 미칠 영향을 승인 전에 살펴볼 수 있다.
- **AI 안내** · 분석 목적과 진단 요약, 후보 처리 방법을 설명의 근거로 제공한다. AI 결과는 화면의 안내로 표시하며, 실제 변경은 사용자가 승인할 때 적용한다.
- **버전과 이력** · 원본을 보존하고 승인된 처리를 새 버전으로 기록한다. 승인 내용을 취소하거나 이전 버전으로 돌아가 다른 처리안을 비교할 수 있다.

## 5. 실행 및 재현 방법

Node.js 20 이상이 필요하다. 저장소 루트에서 다음 명령을 실행한 뒤 브라우저에서 `http://localhost:3000`을 연다. 별도로 설치할 npm 패키지는 없다.

```powershell
cd src
$env:OPENAI_API_KEY = "발급받은_API_키"
npm start
```

`OPENAI_API_KEY`는 AI 안내를 사용할 때 필요하다. 호환 API를 사용하는 경우 `AI_API_URL`과 `AI_MODEL`을 해당 제공자에 맞게 설정할 수 있다.

Render에서는 이 저장소의 `main` 브랜치로 **Web Service**를 생성한다. Root Directory는 `src`, Runtime은 Node, Build Command는 `npm install`, Start Command는 `npm start`로 설정하고, 환경 변수에 `OPENAI_API_KEY`를 등록한다.

## 6. 검증 현황 및 시연 절차

저장소 소스에서 진단 로직, 비교 화면, 승인 이력, CSV 내보내기와 AI 중계 경로를 확인했다. 합성 입력으로 정상 범위 밖의 통계 후보와 규칙 위반이 별도로 집계되는지, IQR이 0이거나 유효 수치가 부족하면 미평가로 표시되는지 검증했다. 이 확인은 기능 검증이며 실제 데이터의 탐지 정확도는 별도 평가가 필요하다. 아래 항목은 시연 때 재현할 절차다. 브라우저 실행 결과, 라이브 API 응답, Render 접속 결과에 대한 검증 기록은 확보되지 않았다.

| 검증 항목 | 재현 방법 | 통과 기준 |
| --- | --- | --- |
| 품질 진단 | 결측값·중복 행·수치형 이상 후보가 포함된 CSV를 불러온다. | 예상한 문제 유형과 검토 대상이 표시된다. |
| 시뮬레이션·복원 | 처리 후보를 비교하고 하나를 승인한 뒤 이전 버전으로 돌아간다. | 비교 지표와 승인 결과를 확인할 수 있고, 복원하면 이전 버전의 행 수와 값으로 돌아간다. |
| 결과 내보내기 | 현재 버전을 CSV로 저장하고 다시 불러온다. | 행·열과 값이 내보낸 버전의 내용과 일치한다. |
| AI 안내 | 서버 키를 설정하고 예시 데이터에서 AI 안내를 요청한다. | 진단 요약에 근거한 설명이 표시되고, 정제 적용은 사용자 승인으로 이뤄진다. |
| Render 배포 | 배포 주소와 `/healthz`를 열고, 예시 데이터로 AI 안내를 요청한다. | 앱과 상태 확인 경로가 응답하고 AI 안내가 표시된다. |

## 8. 한계 및 개선 방향

- 수치형 이상 후보의 실제 오류 여부는 원자료와 분야별 기준을 통해 판단해야 한다.
- AI는 전달된 요약을 바탕으로 안내하므로, 데이터 수집 맥락과 정제 목적은 사용자가 확인해야 한다.
- 후속 작업으로 Excel 입력 지원, 진단 및 CSV 내보내기 자동 검증, 실제 API 응답과 Render 시연 결과 기록을 검토한다.
