# DataClinic 프로젝트 계획서

> 제공된 서비스 기획을 반영한 초안입니다. 구현 및 검증 결과가 아닌 개발 계획이며, 세부 설계 제안은 아래에 구분했습니다.

## 1. 프로젝트 개요
- 서비스명: DataClinic - AI 기반 데이터 정제 의사결정 지원 서비스
- 팀원: 팀원1, 팀원2, 팀원3 (실명 입력 예정)
- 수행 기간: 확정 예정

## 2. 해결하려는 문제
데이터 비전공자는 이상치에 대한 적절한 정제 방법을 판단하기 어렵습니다. DataClinic은 AI가 정제 방법의 근거와 위험성을 설명하고, 사용자가 직접 정제 결정을 내릴 수 있도록 지원하는 서비스입니다.

## 3. 주요 기능 및 활용 AI 기술
| 기능 | 계획 내용 | 활용 기술 |
| --- | --- | --- |
| 데이터 품질 자동 진단 | 엑셀·CSV 업로드 시 결측치, 중복 데이터, 이상치 의심 값 탐지 | Python, pandas |
| 분석 목적 기반 AI 정제 가이드 | 분석 목적과 데이터 특성에 맞는 정제 방법, 추천 근거, 주의사항 설명 | Gemini API |
| 잘못된 정제 결정 사전 경고 | 무분별한 결측치 대체 및 이상치 삭제에 따른 데이터 왜곡 가능성 경고 | 정제 위험 판단 로직, AI 설명 |
| 정제 결과 시뮬레이션 | 방법별 데이터 손실률, 결측률, 통계적 변화 비교 | pandas, 비교 시각화 |
| 사용자 선택형 정제 및 다운로드 | 사용자가 방법을 직접 선택하고 결과를 확인한 후 파일 다운로드 | Streamlit |

## 4. 서비스 이용 흐름 및 구성
파일 업로드 → 분석 목적 입력 → 데이터 품질 진단 → AI 가이드·주의사항 확인 → 정제 방법별 시뮬레이션 비교 → 사용자 선택 → 정제 결과 확인·다운로드

| 구성 요소 | 역할 |
| --- | --- |
| Streamlit 화면 | 파일 업로드, 분석 목적 입력, 방법 선택, 비교 결과 및 다운로드 제공 |
| pandas 진단·정제 모듈 | 품질 진단, 정제 후보 적용, 지표 계산 |
| Gemini 연동 모듈 | 분석 목적과 데이터 특성을 바탕으로 정제 근거 및 주의사항 설명 |
| 경고·시뮬레이션 모듈 | 선택의 위험성 안내 및 방법별 변화 비교 |

AI는 선택의 근거를 설명하고, 최종 정제 방법은 사용자가 결정하는 구조로 계획합니다.

## 5. 기대효과·활용 대상·확장 가능성
- 기대효과: 잘못된 정제 결정을 예방하고 비전공자의 데이터 활용 능력 및 분석 결과의 신뢰성을 높입니다.
- 활용 대상: 데이터 분석 경험이 부족한 대학생, 연구 입문자, 일반 사무직 및 엑셀 데이터를 활용하는 비전공자
- 확장 가능성: 머신러닝 분석 목적별 정제 추천, 데이터 품질 검증 자동화, 사용자 맞춤형 전처리 교육 서비스

## 7. 개발 일정 (기간 확정 예정)
| 단계 | 작업 | 주 담당 | 산출물 |
| --- | --- | --- | --- |
| 1 | 요구사항 및 진단 기준 설계 | 전체, 팀원1 총괄 | 기능 명세 및 샘플 데이터 |
| 2 | 진단·정제·시뮬레이션 개발 | 팀원1 | 데이터 처리 모듈 |
| 3 | AI 가이드 및 위험 경고 개발 | 팀원2 | Gemini 연동 및 경고 모듈 |
| 4 | 화면 개발 및 기능 통합 | 팀원3, 전체 | Streamlit 프로토타입 |
| 5 | 검증, 배포 및 제출 자료 작성 | 전체 | 테스트 결과, 보고서, 발표 자료, 시연 링크 |

## 8. 검증 계획 (세부 기준 제안)
| 항목 | 검증 방법 | 통과 기준 |
| --- | --- | --- |
| 품질 진단 | 결측치·중복·이상치 후보를 의도적으로 넣은 샘플과 비교 | 기대값 및 탐지 기준 확정 예정 |
| AI 가이드 | 동일 데이터에 서로 다른 분석 목적을 입력해 설명 검토 | 근거·주의사항 포함 여부 검토 |
| 위험 경고 | 과도한 삭제 및 대체 시나리오로 경고 확인 | 경고 조건 및 임계값 확정 예정 |
| 시뮬레이션 | 변경 전후 지표를 별도 계산값과 비교 | 지표 정의 및 허용 오차 확정 예정 |
| 다운로드 | 다운로드 파일 재로딩 후 선택 결과와 비교 | 행·열 및 값 일치 확인 예정 |

데이터 손실률, 결측률의 분모와 통계 비교 항목은 구현 전에 명확히 정의합니다. 이상치 의심 값은 실제 오류로 단정하지 않고 탐지 방법과 기준을 함께 표시하도록 설계를 검토합니다.

## 9. 데이터 및 외부 서비스
- 입력: 사용자 업로드 엑셀·CSV
- AI: Gemini API 연동 예정
- 테스트: 합성 샘플 데이터 우선 활용 제안
- 데이터 출처·이용 조건·API 사용 조건: 선정 후 기록 예정

## 10. 구현 시 검토할 사항 (설계 제안)
- 원본을 보존하고 복사본에 정제 후보를 적용하는 방식
- Gemini에 전달할 데이터 범위 및 사용자 안내 방식
- API 키를 서버 환경 변수로 관리하고 공개 저장소에 포함하지 않는 방식
- API 오류 시 진단 결과를 유지하고 재시도 또는 안내를 제공하는 방식
- 통계적 이상치와 실제 입력 오류를 구분해서 설명하는 방식
